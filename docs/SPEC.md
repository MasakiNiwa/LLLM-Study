# ローカルLLM学習アプリ 仕様書

## コンセプト

**自分のペースで使えるローカル LLM タイプの学習アプリ。**

- カレンダーページで学習履歴を確認できる
- 最新の記憶アルゴリズム（FSRS）で、記憶に残るように復習を管理する
- 学習教材は外部の高性能な最新 AI に作ってもらい、そのデータを取り込んで使う
  （教材の仕様をプロンプト・ファイルで AI に渡す）

## 基本方針

- **LLM にすべてを判断させない。** 復習のスケジュール・出題順・正誤の判定はプログラム（アルゴリズム）が行い、
  LLM はその上に乗ってリアクション・解説・一緒に悩む・例文づくり・チャットでの掘り下げを担当する
- **アプリと LLM は構造化データでつなぐ。** アプリの状態（今日の学習状況・見ているカード）を JSON で渡し、
  学習記録が必要なときは LLM がツール（関数呼び出し）でプログラムに問い合わせる
- **LLM の性格タイプをユーザーが選べる**（ともだち・やさしい先生・熱血コーチ・ねこ先輩・執事・カスタム）
- 学習内容は単語帳に限らず広げられるよう、教材の項目は「種類（type）」で拡張できる形にする
- 既存のライブラリを積極的に使い、将来の拡張性・保守性を重視する
- 作って公開 → 確認 → 改善を小さく繰り返す（PR 単位でフェーズを進める）

## UI / デザイン

- スマホ・PC 両対応（`md` = 768px 未満をスマホレイアウト）
  - スマホ: 画面下部にナビゲーションバー（ホーム / 学習 / 教材 / カレンダー / AI）。
    AI モデル・設定・ヘルプはヘッダー右端のメニュー
  - PC: 左サイドバー（メイン 5 項目＋ AI モデル・設定・ヘルプ）
- ライト / ダーク / システム連動テーマ
- アプリヘッダーには GitHub リンクを置かない。GitHub のリリース履歴へのリンクはアプリ内のどこにも置かない
- GitHub リポジトリへのリンクはヘルプページにのみ置く

## アーキテクチャ

```
┌──────────────── メインスレッド（UI） ────────────────┐     ┌──── Engine Worker（classic） ────┐
│ React + Zustand                                      │     │ @litert-lm/core（WebGPU / Wasm）  │
│  pages/      ホーム・学習・教材・カレンダー・AI …    │ ⇄  │  Engine / Conversation            │
│  features/   study, library, calendar, chat, ai …    │     │  ツール呼び出しのループ           │
│  lib/srs     FSRS（ts-fsrs）・出題キュー              │     │  OPFS へのモデル保存              │
│  lib/db      IndexedDB（Dexie）                       │     └───────────────────────────────────┘
│  lib/llm/client.ts ── Comlink ───────────────────────┤     ┌──── Data Worker ──────────────────┐
│  lib/data/client.ts ─ Comlink ───────────────────────┼──── │ 教材パックの解析・検証（zod）     │
└──────────────────────────────────────────────────────┘     │ カレンダーの集計（IndexedDB 直読）│
                                                             └───────────────────────────────────┘
```

### 学習（プログラムが判断する部分）

- **FSRS**: [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs)（FSRS-6）で次回の復習日を計算する
  （`src/lib/srs/scheduler.ts`）。目標の記憶率・最大間隔・当日中の短期ステップ・予定の分散（fuzz）は設定で変えられる
- **出題キュー**: 学習中（分単位）→ 期限の古い復習 → 新しいカード（1 日の上限まで、復習の間に均等に混ぜる）
  （`src/lib/srs/queue.ts`。純粋関数でテスト済み）
- **学習日**: 「1 日の始まり」（既定 4 時）より前は前日として数える（`src/lib/srs/day.ts`）
- **評価の保存と取り消し**: 評価のたびに評価前のカードの状態を記録に残し、正確に取り消せる
- **選択問題の正誤**はアプリが判定し、すすめる評価（正解→「正解」、不正解→「もう一度」）を示す

### AI（LLM が上に乗る部分）

- **ペルソナ**（`src/features/ai/personas.ts`）: 口調・性格の説明（システムプロンプト用）と、
  モデルが無くてもすぐ出せる「ひとこと」のテンプレート（評価への反応・あいさつ・連続正解など）
- **評価へのひとこと**: まずアプリがテンプレートから選んで即表示し、設定が「AI が考える」ならモデルの言葉に差し替える
- **カードの AI 補助**: 解説 / 例文 / 覚え方 / 一緒に悩む。カードの内容と学習状況を JSON で渡す単発の生成
- **チャット**: 送信のたびにアプリの状態（今日の学習状況・連続日数・教材・添付したカード）を
  `<app_state>` の JSON にしてユーザーの発話の前に付ける（前回と同じなら付けず、KV キャッシュを活かす）
- **ツール**（`src/features/ai/tools.ts`）: `get_study_status` / `search_items` / `get_weak_items` / `get_review_history`。
  LiteRT-LM の関数呼び出し（`preface.tools` と `tool_calls`）で、Worker がモデルの呼び出しを受け、
  メインスレッドのプログラムが DB を調べて結果を返す
- 推論は Try Local と同じく専用 Web Worker（classic）＋ WebGPU（無ければ CPU）。
  `src/lib/llm/types.ts` の型だけを UI が参照し、LiteRT-LM 固有の型は Worker に閉じ込める

### モデルの保存・共有・バックアップ

- [共通モデル保存仕様](SHARED_MODEL_STORAGE.md)（Try Local と共通）に従い、OPFS の `shared-models/` に保存する。
  同じ github.io（masakiniwa.github.io）の他のサイトが保存したモデルも一覧に出て、そのまま使える
- 端末のファイルとして書き出せる（PC は保存先を選んでストリーム書き出し、スマホは通常のダウンロード）
- モデルの入手先は Try Local と同じカタログ（Gemma 4 E2B / E4B の Web 版、CPU 向けに Qwen3 0.6B）

### 教材パック（外部 AI との受け渡し）

- 形式は [教材パック形式](STUDY_PACK_FORMAT.md)（`lllm-study-pack` v1）。zod のスキーマ（`src/lib/packs/schema.ts`）が唯一の正で、
  アプリ内の検証・型・外部 AI に渡す JSON Schema・仕様書（Markdown）・プロンプトはすべてここから作る
- 項目の種類: 単語（vocab）・フレーズ（phrase）・一問一答（qa）・穴埋め（cloze）・選択問題（choice）
- 1 つの項目から複数のカードを作れる（例: 単語は「意味を答える」「単語を答える」）。教材ごとに選べる
- 取り込み: 貼り付け・ファイル。AI が付けがちなコードブロック・前後の文章・末尾のカンマを許容し、
  形式の誤りは場所付きで表示する（AI に直してもらうためにそのまま伝えられる）
- 同じ ID の教材を取り込むと更新。同じ項目 ID の学習記録は引き継ぎ、無くなった項目は削除する
- サンプル教材は `public/packs/` に置き、`npm run packs` が検証して一覧（`index.json`）・JSON Schema・仕様書を生成する

### データ

- IndexedDB（Dexie、DB 名 `lllm-study`）: `packs` / `items` / `cards` / `reviews` / `chat` / `meta`
- 設定は localStorage（`lllm-study:settings`）
- 学習データの完全バックアップ（JSON）と復元、学習記録だけのクリア、全削除

### 並列化・GPU の活用

- **Engine Worker**: LLM の推論（WebGPU）・モデルのダウンロードと OPFS 保存
- **Data Worker**: 教材パックの解析・検証、カレンダーの集計（IndexedDB を Worker から直接読む）
- トークンの描画は `requestAnimationFrame` 単位にまとめ、Markdown はブロック単位でメモ化
- ホーム以外のページは遅延読み込み

## ディレクトリ構成

```
src/
  app/          レイアウト・ナビゲーション・起動処理
  pages/        ルート単位のページ
  features/     機能単位（study / library / calendar / chat / ai / items / engine / models / settings / help）
  components/ui 汎用 UI 部品
  lib/          srs（FSRS・キュー・学習日）, db（Dexie・バックアップ）, packs（形式・取り込み・仕様書）,
                llm（Worker・クライアント・OPFS）, data（Data Worker・集計）, speech（読み上げ）, env, utils
public/packs/   サンプル教材（JSON）と一覧
build/          Vite プラグイン（LiteRT-LM Wasm のセルフホスト）
scripts/        ライセンス一覧・サンプル教材の検証と生成
```

## ライセンス管理

- アプリ本体: MIT（`LICENSE`）
- サードパーティ: `npm run licenses` が本番依存を再帰的に収集し
  - `THIRD_PARTY_NOTICES.md`（リポジトリで管理。CI で最新か検証）
  - `public/licenses.json`（ビルド時生成。ヘルプページでライセンス全文を表示）
- ライセンス文を同梱していないパッケージ（`@litert-lm/core` など）は `scripts/license-texts/` の標準文を添付
- サンプル教材: 本リポジトリのオリジナル（MIT）。各パックの `license` / `source` に記載
- AI モデル: 本リポジトリには含めない（各モデルのライセンス・利用規約が適用される）
